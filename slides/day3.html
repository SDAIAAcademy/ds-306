Today a language model enters, and it is treated like any other instrument: calibrated against the gold set, tested for repeatability, checked by group. Say early and clearly that the full runs used today are synthetic recordings; participants with a working key run a few live calls and compare. Breaks are yours: press B.

Four questions, one per session: how good is it, how repeatable, for whom, and is that good enough to replace a person. Each lab starts from the recorded runs, so nothing depends on a key or on yesterday.

Within the budget

Ten complaints a request: the prompt is paid once per batch

  • One request labels ten complaints, each line id: text
  • The gold set is 30 requests; all 20,000 complaints are 2,000
  • Free tier: 50 requests a day, 1,000 after a one-time 10 credits
A measurement choice. Batching can change labels: a complaint is read next to nine others. The stretch of Lab 3.1 compares one-per-call with batches.

Limits from OpenRouter's documentation, read this month. Batching is a trade: fewer requests and tokens against a possible context effect. A careful study measures it; the stretch does with a key. Sources: OpenRouter API rate limits.

Ask it twice

Two kinds of instability: the same prompt again, and the same request in other words

Run stability

Prompt 1, three runs at the same settings. Sampling makes the labels vary.

Prompt stability

Prompt 2 says the same thing differently and adds a rule for two-problem complaints. Wording moves labels.

Both are part of the measurement error of one label. A single run shows neither.

Read prompt 2 aloud. Nobody would call it a different instruction, which is the point: a researcher choosing between two equally reasonable prompts is choosing between two label sets.

The decision of the day. Make the room write criteria before the lab prints anything.

The decision

Can Fahim replace the second coder, and can its labels feed an estimate?

Replace a coder

Each label is used as it is, complaint by complaint. The bar is what a second person adds.

Feed an estimate

Labels are counted. Errors can be measured on a human sample and corrected in the count.

Two questions, two bars. A model can fail the first and pass the second.

Keep the two questions apart all session. Most teams merge them and decide "the model is good enough" or "not good enough" for everything at once.

Three things to keep

Version everything

Model, prompt hash, settings and date travel with every label set.

Ask it twice

Run and prompt stability are part of a label's error; a single run hides both.

Report by group

A gap by variety turns into an under-count by district.
